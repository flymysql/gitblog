写给完全没用过 AI 编程工具的人。全程不需要会写代码，你只要会提问、会看结论。

官方资料：DSH 文档 · DeepSeek API 文档 · 开放平台

一、装 DSH（5 分钟）

它是什么：跑在你自己电脑上的 AI 助手。能读你指定的文件夹、能自己跑命令、动手前会问你。聊天机器人给你答案，它给你结果。

分两条路，小白走第一条：

是什么 适合谁
DSH Desktop（推荐） 社区维护的桌面客户端，一键安装包，不需要命令行和 Node.js 绝大多数人
官方 Harness deepseek-ai/deepseek-harness 源码 / CLI 开发者

打开官网 https://dshdesktop.cn，点「为 Windows 下载」或「为 macOS 下载」：

说明一下：DSH Desktop 是社区独立维护的开源项目，不是 DeepSeek 官方产品（官网自己也标了这句话）。想用官方版本就走上面那条 CLI 路线。旁边那个「下载 Next 版」是更新更快的分支，小白先用普通版。

装完双击打开，就是这个样子：

安装包 200~500 MB 是正常的（自带运行时，不用另装 Node.js）。

  • Windows 弹「Windows 已保护你的电脑」→ 更多信息 → 仍要运行
  • macOS 提示无法验证开发者 → 系统设置 → 隐私与安全性 → 仍要打开

第一次打开：只认这三个地方

  1. ① 左下「选择工作区」 —— 选一个文件夹（比如放插件、放代码的那个目录）。 没选之前输入框是灰的、点不动，这不是坏了 —— 这是新手最容易卡住的地方。它只看得到你选中的那个文件夹。
  2. ② 输入框 —— 选中工作区后才能输入。新任务的第一次提问，建议永远加一句 先不要修改任何文件。
  3. ⚙ 设置 → 模型 —— 填 API Key（下一节）。

一个小习惯：一个任务开一个新会话，别把改插件和写周报混在一起。

二、配模型：注册 → 充值 → 取 Key（5 分钟）

从 https://platform.deepseek.com/ 开始（注意：和聊天版 chat.deepseek.com 不是一个站，只有开放平台里才有 API Key）。

第 1 步｜注册登录：手机号收验证码，或者微信扫码。

第 2 步｜充值：左侧「充值」→ 选金额 → 支付宝 / 微信扫码。第一次充 ¥20 就够用很久。

第 3 步｜创建 API Key：左侧「API keys」→ 点右上角「创建 API key」。

创建出来的那串 sk-… 只显示这一次，立刻点「复制」：

⚠️ 它是你的钱包，不要发给别人、不要粘进代码或 GitHub（GitHub 上有机器人 7×24 扫这种字符串，几分钟就能刷爆）。泄露了立刻去 API keys 页删掉重建。

第 4 步｜粘进 DSH：设置 → 模型 → DeepSeek 卡片粘 Key → 保存。立即生效，不用重启；密钥只写不读（页面上只显示脱敏结果）。

三、直接抄的 prompt

它最容易犯的错是"你一句话交代完、它就开始瞎改"。 下面这段整体复制给 AI 就行（开头两句换成你自己的事）：

我要处理的是：我们发布的一个 Chrome 插件（给淘宝卖家批量上传证书用的）被用户反馈"新版装不上、旧版也有问题"，请帮我定位到底哪里出了问题，修好并重新打包。 相关文件：插件源码目录，以及新旧两个版本的安装包（两个包需要对比）。

  1. 先只读，不要修改任何文件；用大白话告诉我这个插件是什么、文件结构是什么、用户点一下之后关键流程怎么走。
  2. 把上面那段抱怨拆成 3 条能用命令验证的技术假设：假设是什么、在哪个文件哪一行能看到证据、用什么命令能证实或推翻。先不要下结论。
  3. 写脚本自己去验，结果做成一张对照表；每条结论都要附文件名 + 行号 + 能复现的命令或输出，说不清的地方直接写"不确定"，不要猜。
  4. 先给我修复方案（改哪里、为什么、怎么验证），我确认之后再动手；每改一处配一个不用浏览器、不用网络的测试用例，并把错误写法写成"必须失败"的反例。
  5. 最后打包产出，并给一条我能自己跑的验证命令；任何一步失败就直接退出，不要"降级继续"。
  6. 收尾时列清楚：哪些你验证过了（附命令和输出），哪些只是推理，以及升级、使用要注意什么。

换成你自己的活，只要改前面两句：① 一句话说清"谁反馈了什么"（不用贴聊天记录，讲清现象就行）；② 源码和文件放在哪。后面 6 条原样保留——那是让 AI 别偷懒的部分。

第一次用可以先只发第 1 条，确认它真的懂了、没瞎猜，再把整段发过去。

全文最重要的一句：让 AI 明确告诉你 —— 哪些它验证过了，哪些它只是在猜。

四、小白避坑清单

用 DSH 的时候

  1. 没选工作区，输入框是灰的 —— 不是坏了
  2. 一个任务一个会话
  3. 新任务先只读，加一句"不要修改任何文件"
  4. 权限弹窗看清楚再点，那是安全阀
  5. 模型先用 deepseek-flash，便宜且够用
  6. 想省钱就避开工作日 9–12、14–18

关于 API Key

  1. Key 只显示一次，创建后立刻复制
  2. 别往聊天框、代码、GitHub 里粘；泄露立刻删掉重建
  3. 第一次充 ¥20 就够跑很久

让 AI 干活

  1. 一次只让它做一件事，别一句话交代完
  2. 要证据（文件 + 行号 + 可复现命令），不要"我觉得"
  3. 要自检脚本，不要"我改好了"
  4. 要它自己说清楚"哪些没验证过"
  5. 把踩过的坑写成测试用例

发给用户的东西

  1. "我能打开" ≠ "用户能安装"：先验证产物合法，再去 debug 功能，顺序反了会白干几天
  2. 不要写"失败就降级成另一个格式"的兜底 —— 伪格式比明确报错糟糕一百倍
  3. 尽量别换签名私钥，换了等于换了个新插件
  4. 私钥是公章，不要随包分发
